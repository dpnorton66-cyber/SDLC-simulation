What to look for

  1. Push without limits. Run the first scenario. Work keeps entering the system faster than Develop can finish it. WIP climbs, cards turn amber and red, and cycle time grows without a ceiling. Throughput does not improve, because the bottleneck sets the pace.
  2. Pull with limits. Switch on WIP limits. WIP stops growing and cycle time settles. The backlog grows instead, which makes the mismatch between demand and capacity visible rather than hiding it inside the process.
  3. Find the bottleneck. The column that is always full, with finished cards waiting in the column before it, is the constraint. Adding people anywhere else changes nothing. Try it.
  4. Set limits per column. Turn off the single limit and set each column separately. A tight limit at the constraint and a small buffer just upstream of it keeps the bottleneck fed without letting work pile up elsewhere.
  5. Little's Law. Cycle time equals WIP divided by throughput. The predicted figure uses the WIP on the board now; the measured figure comes from items that finished recently but started some time ago. When WIP is still growing the prediction runs ahead of the measurement. If throughput is fixed by the constraint, the only way to shorten cycle time is to hold less WIP.
  6. Variation. Set spread to high and compare. Uneven item sizes make queues form even when average capacity matches demand. Limits and smaller, more even items both help.
